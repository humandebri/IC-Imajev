# LoRAの64出力共有による命令数削減

既存の32出力タイルを2枚まとめ、同じ入力の読み出しとsplatを共有する候補をローカルcanisterで測定した。重みの量子化や配置は変えず、各出力に対するF32の乗算・加算と列の順序を維持する。計算途中の和は64出力分を確保する。

比較元は現在の全体推論モジュール6052cc94…が採用したF32 WATと同じSHA256（25b6a171…）。同一の診断モジュール713d3f8c…に32出力版と64出力版を入れ、同じ入力と重みで比較する。計測区間にはF32入力の展開と投影を含み、出力digest計算・Candid応答生成は含まない。全体推論の計測ではない。

|行列|形状|保存済み実入力での削減率|
|---|---|---|
|gate-A|64×2560|1.545～1.551%|
|down-B|2560×64|3.652～3.711%|

down-A（64×9216）は合成入力で1.065～1.509%減少した。全3形状・36ケース・72回の通常queryで、双方の出力digestがnative scalar oracleと一致した。符号・極小値の境界試験を含む全ケースの削減率は、gate-A 1.091～1.554%、down-B 1.846～5.664%、down-A 1.065～1.509%。保存済み応答の再デコード、入力と重みのhash、build依存物のhash、計測counterの整合も再検証した。

実入力は以前のprefix/617/insufficient/maximumで採取した活性値。現在の短文入力そのものを再実行した値ではない。57/59/67 tokenも保存済み活性値の先頭を切り出したサイズ別の投影試験である。符号付きゼロ・正負・極小値を含む合成入力で1/3/7/8/32/64/88/132 tokenも確認する。down-A（64×9216）はqueryの入力サイズ上限のため、合成入力の1/3/7/8/32/45 tokenで確認する。

各出力全体のSHA256を、元の列順で計算するnative scalar oracleと比較する。判断ラベルだけの一致で済ませず、32出力版と64出力版の双方をoracleに照合する。ただし、確認対象はこれらの行列・入力であり、全モデルの状態や最終判断までの比較ではない。

旧132 token構成の全体profileではLoRA A/Bが11.51%だった。この比率を単純に当てはめると、投影の1.5～3.7%削減は全体の約0.2～0.4%に相当する。これは現在の短文構成の全体実測値ではなく、効果の規模を判断する目安に限る。現在の39 query経路が減ることも確認していない。

この結果は小さな削減候補である。大きな削減には、旧profileで66.32%を占めたINT8基底行列積の改善を優先する。既試験のINT8奇数末尾処理は87 tokenの投影で0.8397%減ったが、全体への接続と確認が残っている（[残りの効率化](REMAINING_EFFICIENCY.md)）。LoRAのINT8化やbase重みへのmerge後の再量子化は数値を変えるため、判断精度の再評価が必要になる。

生成器はscripts/build_f32_output64_probe.py、計測器はscripts/check_f32_output64_probe.py、保存された応答とhashの再検証・集計はscripts/report_f32_output64_probe.py。証跡はartifacts/f32-output64-v1/{build-v2,gate-A,down-B,down-A}、集計はartifacts/f32-output64-v1/report.json。生成物はgitignore対象で、source ZIP、依存rlibのhash、Wasm patch検証、入力・重み・Candid応答を保存している。

専用ローカル診断canister 2sm34-hd777-77775-aaauq-caiだけにインストールした。全体推論6eyddのモジュールは6052cc94…のまま読み取り確認。ランタイムへの採用・全体推論の入れ替えは行っていない。採用時には部分行列の32出力fallback、列継続処理、全モデル出力・命令数の検証が必要になる。
